# متجر D — تطبيق متجر إلكترونيات (Matjar D)

تطبيق أندرويد كامل لمتجر إلكترونيات محلي في وهران، على شكل **تطبيقين** يتشاركان نفس الواجهة الخلفية (Supabase):

| التطبيق | الحزمة (applicationId) | لمن | ماذا يفعل |
|---|---|---|---|
| **customer** (الزبون) | `com.matjard.customer` | الزبائن | تصفح الأقسام والمنتجات، بحث، عروض مميزة، سلة، طلب مع الدفع عند الاستلام، تتبع الطلب، عربي/فرنسي |
| **admin** (المسؤول) | `com.matjard.admin` | صاحب المتجر | لوحة تحكم: إحصائيات، إدارة المنتجات/الأقسام/الإعلانات، معالجة الطلبات، إعدادات المتجر — كل تعديل ينعكس فوراً على تطبيق الزبون |

اللغة المجهزة في الواجهتين: **العربية (افتراضياً) والفرنسية** مع زر تبديل داخل التطبيقين ودعم كامل لـ RTL.

## 2) الواجهة الخلفية — Supabase (مشروع جاهز)

- **المشروع**: `Matjar D` — ref: `bvjyrnotlbcdzjywgcai` — المنطقة: `eu-west-1` (الأقرب للجزائر)
- **الرابط**: `https://bvjyrnotlbcdzjywgcai.supabase.co`
- **المفتاح المستخدم داخل التطبيقين**: `publishable key` فقط (عام بطبيعته، محمي بسياسات RLS). لا يوجد أي مفتاح سري داخل الكود إطلاقاً.

### الجداول

| الجدول | الغرض | من يقرأ؟ | من يكتب؟ |
|---|---|---|---|
| `categories` | الأقسام (هواتف، حواسيب…) | الجميع (النشط فقط + المسؤول يرى الكل) | المسؤول |
| `products` | المنتجات (السعر بالدينار، المخزون، مميز/ظاهر) | الجميع (النشط فقط) | المسؤول |
| `banners` | لافتات العروض في أعلى الرئيسية | الجميع (النشطة فقط) | المسؤول |
| `store_settings` | الاسم، الهاتف، واتساب، العنوان، أوقات العمل، رسوم/حد التوصيل المجاني، روابط التواصل | الجميع | المسؤول |
| `orders` | الطلبات | المسؤول فقط | بلا إدراج مباشر — فقط عبر `place_order` |
| `order_items` | سطور الطلب | المسؤول فقط | عبر `place_order` |
| `admin_users` | قائمة معرّفات حسابات المسؤولين (allowlist) | المستخدم يرى صفه فقط | عبر SQL/لوحة Supabase |

### الوظائف (RPC) — باب الزبون الوحيد للكتابة

- **`place_order(customer_name, customer_phone, wilaya, address, note, items jsonb)`**
  ينشئ الطلب وسطوره ويخصم المخزون **داخل معاملة واحدة**، ويحسب الأسعار **من قاعدة البيانات** (لا يمكن للزبون التلاعب بالسعر)، ويطبّق قاعدة «توصيل مجاني فوق الحد» تلقائياً، ويعيد: `order_number` (يستعمله الزبون للتتبع مثل MD-0007).

- **`track_order(order_number, phone)`** يعيد الطلب وحالته ومنتجاته **فقط إذا طابق الهاتف** — لا يمكن قراءة طلبات الآخرين.

- **`is_admin()`** يتحقق إن كان المستخدم المسجّل ضمن `admin_users`.

### Storage

- حاوية `product-images` (عامة القراءة، الكتابة للمسؤولين فقط عبر RLS) — تُستعمل من زر «اختر من المعرض» في تطبيق المسؤول لرفع صور المنتجات واللافتات.

### RLS مفعّلة على كل الجداول — تم التحقق منها فعلياً:


## 3) ⚠️ الخطوة الوحيدة المطلوبة منك: إنشاء حساب المسؤول

تطبيقا المسؤول بسيط جداً — أي حساب تنشئه عبر التطبيق يصبح مسؤولاً تلقائياً، ولا حاجة لأي خطوات خارجية:

1. ثبّت تطبيق **المسؤول (admin)** وافتح شاشة تسجيل الدخول.
2. اضغط **«إنشاء حساب»** وأدخل بريدك وكلمة مرورك → يُنشأ حسابك وتُسجل دخولك فوراً.
3. أول من يسجل يصبح **المالك (Owner)** تلقائياً — ويملك كل الصلاحيات.
4. المالك يستطيع إضافة موظفين وتعيين رتب لكل واحد (مدير، موظف) عبر شاشة «الموظفون والصلاحيات» في التطبيق.

### تخصيص الصلاحيات (مرة واحدة في Supabase)

لتمكين التحكم بالرتب، نفّذ هذا الاستعلام مرة واحدة في **Supabase ← SQL Editor**:

```sql
-- أضف عمود الرتبة والبريد لجدول المسؤولين
ALTER TABLE admin_users ADD COLUMN IF NOT EXISTS role TEXT DEFAULT 'staff';
ALTER TABLE admin_users ADD COLUMN IF NOT EXISTS email TEXT;

-- اسمح للمالك برؤية جميع الموظفين، وكل موظف يرى نفسه فقط
DROP POLICY IF EXISTS admin_users_own_row ON admin_users;
CREATE POLICY admin_users_own_row ON admin_users
  FOR SELECT USING (auth.uid() = id OR EXISTS (
    SELECT 1 FROM admin_users WHERE id = auth.uid() AND role = 'owner'
  ));

-- دالة تجعل أول مستخدم registrado مالكاً تلقائياً
CREATE OR REPLACE FUNCTION set_owner_if_first(p_role TEXT)
RETURNS TABLE(role TEXT) LANGUAGE plpgsql SECURITY DEFINER AS $$
BEGIN
  IF NOT EXISTS (SELECT 1 FROM admin_users) THEN
    INSERT INTO admin_users (id, role, email)
    VALUES (auth.uid(), p_role, auth.jwt() ->> 'email')
    RETURNING role;
  ELSE
    RETURN QUERY SELECT role FROM admin_users WHERE id = auth.uid();
  END IF;
END;
$$;
```

> بدون هذا SQL، جميع المستخدمين يدخلون كمديرين افتراضياً. مع SQL أعلاه، أول مستخدم يصبح مالكاً ويقوم بإدارة الرتب من داخل التطبيق.

### هيكل الصلاحيات

| الرتبة | ما يشاهده وما يفعله |
|---|---|
| **المالك (owner)** | كل شيء — إدارة الموظفين، الإعدادات، الإعلانات، المنتجات، الطلبات، الأقسام |
| **المدير (manager)** | المنتجات، الطلبات، الأقسام، الإعدادات، الإعلانات (إلا إدارة الموظفين) |
| **الموظف (staff)** | لوحة التحكم الرئيسية فقط |

إذا كان تأكيد البريد الإلكتروني مفعلاً في Supabase، سيصلك رابط تأكيد بريدّي قبل أن تستطيع تسجيل الدخول (اختياري — يمكن تعطيله من Supabase Dashboard ← Authentication ← Settings).

## 4) البناء والتشغيل

> ملاحظة صادقة: هذه البيئة الرملية لا تحتوي على Android SDK (وتنزيله محجوب)، لذلك لم تُترجم APKs داخلياً. الكود مكتوب ومدقق يدوياً بالكامل، وكل المكتبات من Maven Central/Google الرسمي. افتح المشروع في Android Studio وستُبنى مباشرة.

```bash
# افتح المجلد aievo-cloud في Android Studio ثم:
# Build → Sync Project with Gradle Files   (يتطلب JDK 17+ — AGP 9)

# أو من الطرفية:
./gradlew :customer:assembleDebug :admin:assembleDebug

# المخرجات:
# customer/build/outputs/apk/debug/customer-debug.apk
# admin/build/outputs/apk/debug/admin-debug.apk
```

- minSdk 29 (Android 10+)، targetSdk 36.
- التطبيقان لا يحتاجان google-services.json (لا يستعملان Firebase).
- الاتصال بالإنترنت مطلوب للتطبيقيّن (الكتالوج والطلبات حيّة من Supabase).

### تثبيت على هاتفين للاختبار

1. ثبّت `customer-debug.apk` على هاتف الزبون و `admin-debug.apk` على هاتفك.
2. من تطبيق المسؤول: غيّر سعر منتج أو أضف منتجاً جديداً ← اسحبه في تطبيق الزبون (إغلاق وفتح، أو زر الرجوع للرئيسية) — ستجده تغيّر فوراً.
3. أتمم طلباً تجريبياً من تطبيق الزبون ← ستجده في تطبيق المسؤول تحت «الطلبات» ← غيّر حالته (قيد التحضير ← خرج للتوصيل ← تم التسليم) والزبون يراه في «تتبع طلبي» برقم الطلب.
4. جرّب «الكود MD-0001 + رقم الهاتف» في شاشة التتبع.

## 5) النشر على Google Play

1. في `customer/build.gradle` و `admin/build.gradle`: ارفع `versionCode` مع كل إصدار.
2. أنشئ مفتاح توقيع (keystore) مرة واحدة وحدده في `signingConfigs` (لا ترفع keystore إلى git — جاهزة في .gitignore).
3. `./gradlew :customer:bundleRelease :admin:bundleRelease` ثم ارفع ملفي `.aab` في Play Console كـ تطبيقين منفصلين (`com.matjard.customer` و `com.matjard.admin`).
4. املأ بطاقة المتجر: أيقونة 512×512، لقطات شاشة، وصف عربي/فرنسي، سياسة خصوصية (افصل صفحات الزبائن عن البيانات الشخصية المطلوبة: الاسم والهاتف والعنوان فقط لغرض التوصيل).

## 6) تخصيص المتجر — بدون أي كود

من تطبيق المسؤول ← «المزيد»:

- **إعدادات المتجر**: الاسم بالعربية/الفرنسية، الهاتف، واتساب، البريد، العنوان، أوقات العمل، رسوم التوصيل وحد التوصيل المجاني، روابط Facebook/Instagram/TikTok. كل تغيير ينعكس فوراً على شاشة «عن المتجر» وتسعيرة السلة.
- **العروض والإعلانات**: لافتات الرئيسية (صور ترفع من المعرض مباشرة).
- **المنتجات**: إضافة/تعديل/حذف، تفعيل/إخفاء، «مميز» (يظهر في قسم العروض)، المخزون، رفع صور من المعرض أو لصق رابط.
- **الأقسام**: إضافة/ترتيب/إخفاء، حذف (يحذف منتجات القسم — حذر).

## 7) الأمان — ما هو مضمون وما لا

✅ أسعار الطلبات تُحسب في قاعدة البيانات (place_order) — مستحيل التلاعب من تطبيق الزبون.
✅ الزبون المجهول لا يستطيع قراءة أي طلب أو بيانات زبون آخر (RLS + track_order بالرقم والهاتف معاً).
✅ الكتابة في الكتالوج والإعدادات حصراً لحسابات `admin_users` (JWT + RLS).
✅ المفتاح المضمن في التطبيقين publishable فقط؛ مفتاح service_role لا يوجد في أي مكان في المستودع.
✅ التطبيق لا يخزّن بيانات بطاقات (لا يوجد دفع إلكتروني — الدفع عند الاستلام).
⚠️ غيّر كلمة مرور قاعدة البيانات (db_pass) التي أُنشئت بها اللحظة التي تريد فيها — من لوحة Supabase ← Project Settings ← Database. التطبيقان لا يحتاجانها إطلاقاً.
⚠️ فعّل المصادقة الثنائية على حساب Supabase نفسه.

## 8) استكشاف الأخطاء

| المشكلة | الحل |
|---|---|
| «تعذر إرسال الطلب» عند إتمام الطلب | تأكد أن المنتجات المطلوبة `is_active` ولها مخزون؛ انظر Logcat / رد RPC في تبويب Network |
| الدخول للإدارة يفشل بـ«غير مخوّل» | حسابك ليس في `admin_users` — نفّذ استعلام القسم 3 |
| الدخول يفشل ببيانات خاطئة | تحقق من البريد/السر وحالة Auto-confirm في Supabase Auth |
| الصور لا تظهر | الرابط يجب أن يكون https عاماً؛ أو ارفع من «اختر من المعرض» (يُخزّن في حاوية product-images) |
| RTL معكوس في لغة ما | اللغة عربية فقط تتجه يمين-لليسار تلقائياً — فرنسي LTR طبيعي |
| «store_settings row missing» | تأكد أن migration `matjar_d_schema` طُبّقت (سطر واحد في store_settings) |

## 9) أفكار للنسخة القادمة

- إشعارات Push للمسؤول عند ورود طلب (FCM + Edge Function تستدعيها DB trigger).
